Part 3: Wiring a container · , Chapter 9

Multiple instances of the same type

Our shop is getting busy, so we split the database in two: reads go to a replica, and writes go to the primary. Both are a Database. Let's see how a container keeps two components of the same type apart, without inventing a new type for each.

Two databases, one type

Remember the service locator of Chapter 3, which lost the replica because it filed everything by type? Here nothing gets lost. It's like the keys on your key ring: two of them may be the same make, but one is labelled "front door" and the other "garage", and you never mix them up.

How the container tells them apart

  1. Components have names. In snapfit, a component is known by its field's name, read_db or write_db, never by its type.
  2. deps passes them in order. Because order_store lists deps = [read_db, write_db], ShopContainer::new() calls CqrsOrderStore::new with a clone of read_db first and a clone of write_db second.
  3. Each one has its own getter. The container generates get_read_db() and get_write_db(), both returning an Arc<Database>, each pointing to its own database.

Reads now go to the primary, and writes go to the replica. That's the problem we called arguments by position in Chapter 3. Naming components by field fixed the locator's problem, but a constructor still receives its arguments in order, and the compiler checks their types, not which one we meant. The next chapter shows two ways to pass dependencies by name, so that their order no longer matters.

Which problem this solves

  1. One entry per type (Chapter 3): read_db and write_db have the same type and are still two components, because snapfit names components by field. No wrapper type is needed to tell them apart.

Remember

  1. A container can hold as many fields of the same type as your application needs.
  2. When a constructor takes several arguments of the same type, the order of the names in deps is the only thing that tells them apart, and the compiler can't catch a swapped pair. Chapter 10 passes them by name instead.
